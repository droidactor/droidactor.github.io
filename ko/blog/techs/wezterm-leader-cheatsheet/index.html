WezTerm 사용법 2편 - 리더 단축키 스무 개 관리하기

2026년 8월 25일 · 수정 2026년 11월 5일

요약. 1편에서 Ctrl+U 를 접두키로 두고 분할과 이동과 탭을 잡았습니다. 그렇게 쓰다 보면 다음 문제가 옵니다. 키가 스무 개를 넘어가면서 손이 기억하는 것과 설정 파일에 적힌 것이 어긋나기 시작합니다. 이 글은 키 정의를 표 하나로 모아 실제 바인딩과 도움말을 함께 만드는 방법, 그리고 접두키를 쓰면서 치르는 대가를 다룹니다.

제가 만든 무료 앱입니다. 많이 써 주세요.

키 정의는 표 하나에 모읍니다

2026년 11월 5일 현재 PC의 설정을 기준으로 본문과 첨부 파일을 맞췄습니다. 아래 코드는 바인딩과 메뉴를 만드는 핵심 예제입니다. 전체 파일에는 창·세션 관리, ID 복사와 Herdr 연동도 들어 있습니다.

1편의 방식대로 leader("w", ...) 를 줄마다 늘어놓으면 설명을 적을 자리가 없습니다. 그래서 키·설명·액션을 세 칸짜리 항목 하나로 묶고, 그 목록에서 바인딩을 만들어냅니다. 설명은 주석이 아니라 데이터가 됩니다.

local leader_bindings = {
  { "w", "좌우 분할 (Width)", act.SplitHorizontal({ domain = "CurrentPaneDomain" }) },
  { "v", "상하 분할 (Vertical)", act.SplitVertical({ domain = "CurrentPaneDomain" }) },
  { "z", "현재 pane 확대 / 원래대로 (Zoom)", act.TogglePaneZoomState },
  { "h", "왼쪽 pane 으로 이동", act.ActivatePaneDirection("Left") },
  { "/", "커맨드 팔레트", act.ActivateCommandPalette },
}

for _, b in ipairs(leader_bindings) do
  table.insert(keys, { mods = "LEADER", key = b[1], action = b[3] })
end

이제 같은 목록을 화면에도 띄웁니다. LEADER + . 에 act.InputSelector 를 붙이면 항목이 오버레이로 나오고, 고른 항목의 동작을 그 자리에서 실행합니다. 키를 하나 추가하면 도움말도 같이 늘어나므로 둘이 어긋날 수 없습니다.

wezterm, act, config, keys는 기존 설정에서 만든 변수를 씁니다. 리더는 config.leader = { key = "u", mods = "CTRL", timeout_milliseconds = 2000 }입니다. 다음 두 콜백은 키를 누를 때가 아니라 설정을 읽을 때 한 번만 만듭니다.

local cheatsheet_choices = {}
for _, b in ipairs(leader_bindings) do
  table.insert(cheatsheet_choices, {
    id = b[1], label = string.format("%-12s%s", b[1], b[2]),
  })
end
table.insert(cheatsheet_choices, {
  id = "", label = "1 - 9, 0    탭 선택 (1 = 첫 탭, 0 = 10번째 · 안내)",
})

local cheatsheet_pick = wezterm.action_callback(function(win, p, id)
  if not id or id == "" then return end
  for _, b in ipairs(leader_bindings) do
    if b[1] == id then
      win:perform_action(b[3], p)
      return
    end
  end
end)

local open_cheatsheet = wezterm.action_callback(function(win, pane)
  win:perform_action(act.InputSelector({
    title = "LEADER (Ctrl+U) 단축키",
    fuzzy = true,
    fuzzy_description = "단축키 검색 (↑↓ 이동 · Enter 실행 · Esc 닫기) : ",
    choices = cheatsheet_choices,
    action = cheatsheet_pick,
  }), pane)
end)

table.insert(keys, { mods = "LEADER", key = ".", action = open_cheatsheet })
-- 기존 키를 모두 추가한 뒤 config.keys = keys 로 적용합니다.

표에 담기지 않는 키도 있습니다. 탭 번호는 루프로 만들고 도움말에는 안내 한 줄만 남깁니다. 현재 설정은 탭을 1번부터 셉니다. 1은 첫 탭, 9는 아홉 번째 탭, 0은 열 번째 탭입니다. ActivateTab에 넘기는 인덱스는 0부터이므로 다음처럼 바꿉니다.

for i = 0, 9 do
  table.insert(keys, {
    key = tostring(i), mods = "LEADER",
    action = act.ActivateTab((i + 9) % 10),
  })
end

도움말의 안내 행은 id가 빈 문자열이므로 골라도 실행하지 않습니다. 메뉴 안에서 숫자를 치면 탭을 바꾸는 대신 검색어가 됩니다. 번호로 이동하려면 메뉴를 닫고 Ctrl+U 다음 번호를 누릅니다. 탭 바도 1부터 표시하며, 전체 파일의 tab_and_split_indices_are_zero_based = false와 제목의 tab_index + 1이 그 표시를 맞춥니다.

도움말이 오조작을 만들던 두 가지

fuzzy = true 를 빼면 안 됩니다. InputSelector 의 기본 모드는 각 행에 빠른 선택 문자를 붙이는데, 그 문자가 alphabet 필드의 기본값 1234567890abc… 에서 순서대로 나옵니다. 화면에 적힌 단축키와는 아무 관계가 없습니다.

예전 목록에서는 네 번째 항목이 pane 닫기였습니다. 4번 탭으로 가려고 4를 누르면 그 행이 선택됩니다. 도움말의 행 번호와 탭 번호를 혼동하지 않도록 검색 모드로 고정했습니다.

두 번째는 action_callback을 만드는 시점입니다. 키 핸들러 안에서 다시 호출하면 메뉴를 열 때마다 이벤트 핸들러가 등록됩니다. 단축키 목록과 콜백은 설정 로드 시점에 한 번만 만듭니다. choices 같은 일반 테이블을 새로 만드는 것 자체가 핸들러를 등록하는 것은 아닙니다.

전체 파일은 메뉴를 열 때 현재 GUI의 pid와 window, tab, pane ID를 읽어 (id) 행에 붙입니다. 그 행에서 Enter를 누르면 정보를 복사합니다. 이 ID는 탭 바의 1번·2번 같은 표시 번호와 다릅니다. ID가 들어갈 테이블만 그때 만들고, 선택 콜백은 미리 만든 것을 재사용합니다.

현재 설정의 키와 Herdr 연동

아래 키는 모두 Ctrl+U를 누른 다음 입력합니다. 방향키도 리더 다음에 누르는 방식입니다.

키동작
c / u새 탭 / 새 창
b / n이전 탭 / 다음 탭
1 ~ 9, 0첫 번째 ~ 아홉 번째 탭, 열 번째 탭
w / v좌우 분할 / 상하 분할
h / j / k / l왼쪽 / 아래 / 위 / 오른쪽 pane으로 이동
방향키WezTerm pane 크기 5칸 조절. Herdr에서는 Herdr의 조절량을 따름
z현재 pane 확대 / 복원
x현재 pane 닫기 (WezTerm은 확인 후 닫기)
y현재 WezTerm pane의 스크롤백을 포함한 텍스트 복사
d / apane을 새 창으로 분리 / 다른 탭·창의 pane을 현재 pane 옆에 붙이기
s / eWezTerm의 mux 세션 접속 / 접속 해제
qHerdr 화면에서 분리. 작업은 Herdr 서버에 남음. 일반 pane에서는 동작 없음
/ / .커맨드 팔레트 / 이 단축키 메뉴
Ctrl+U안쪽 프로그램에 Ctrl+U 전달

전체 파일은 herdr = true가 붙은 w, v, z, x, q, h/j/k/l, 방향키를 로컬 Herdr 실행 중에는 Herdr로 전달합니다. 전달할 때는 Herdr 접두키인 Ctrl+B 다음 같은 키로 바꿉니다. 직접 누를 때와 메뉴에서 고를 때 모두 같은 동작을 거칩니다. 탭·창·WezTerm 세션 키는 WezTerm이 처리합니다.

이 전달은 Herdr의 접두키와 [keys] 설정을 맞춰 둔 제 환경을 전제로 합니다. Herdr를 별도로 설치하고 접두키를 Ctrl+B, w를 좌우 분할, v를 상하 분할, 방향키를 크기 조절로 맞춰야 합니다. 자동 감지는 로컬 프로세스 기준이라 SSH 너머·WSL 내부·WezTerm mux 도메인에서는 적용되지 않습니다. 그때는 Herdr 접두키를 직접 씁니다. a로 pane을 붙이는 기능도 mux·SSHMUX pane은 제외합니다.

Herdr를 감지하면 (id) 행에 세션·workspace·tab·pane ID도 붙습니다. --remote 접속은 ID 조회를 생략하고, 환경변수로만 고른 세션은 알아내지 못해 default로 조회합니다. 또한 Herdr의 포커스 정보는 같은 세션을 마지막으로 조작한 클라이언트 기준입니다. 다른 클라이언트도 연결돼 있다면 현재 화면과 다를 수 있습니다.

안 외우는 쪽에는 커맨드 팔레트가 있습니다

단축키로 잡을 것과 잡지 않을 것을 나눠야 합니다. 하루에 몇 번 쓰는 동작까지 리더에 붙이면 목록이 다시 스무 개를 넘습니다. 저는 그 나머지를 커맨드 팔레트에 넘기고 LEADER + / 하나만 뒀습니다.

팔레트는 WezTerm이 아는 명령 전체를 검색하는 모달 오버레이입니다. 타이핑하면 흐릿한 일치로 좁혀지고, 자주 쓴 것이 위로 올라옵니다. 기본 키는 Ctrl+Shift+P이므로 리더에 붙이지 않아도 됩니다. pane 확대는 기본 Ctrl+Shift+Z도 쓸 수 있고, 현재 설정에서는 Herdr와 같은 키로 다루려고 LEADER + z도 추가했습니다.

리더 조합을 셸에 보내는 키도 둡니다

접두키로 쓴 Ctrl+U 한 번은 셸에 도달하지 않습니다. bash에서 커서 앞을 지우던 기능도 그대로는 쓸 수 없습니다. 현재 설정은 Ctrl+U 다음 다시 Ctrl+U를 누르면 안쪽 프로그램에 한 번 전달하도록 했습니다. 두 번째 입력은 리더 대기 시간인 2초 안에 누릅니다. Ctrl+U 다음 Ctrl을 떼고 u만 누르면 새 창이 열리므로 구분해야 합니다.

table.insert(keys, {
  mods = "LEADER|CTRL", key = "u",
  action = act.SendKey({ key = "u", mods = "CTRL" }),
})

리더가 켜진 동안에는 바인딩에 없는 키도 삼켜집니다. 공식 문서의 표현으로도 터미널에 전달되지 않습니다. 그래서 1편의 물결 표시가 장식이 아닙니다. 표시가 없으면 대기 상태인지 확인하려고 누른 키 하나가 그대로 사라집니다. 2초가 지나면 대기는 저절로 풀립니다.

정리

키·설명·액션을 한 표에 모으면 바인딩과 도움말이 같은 원본을 읽습니다. InputSelector는 fuzzy = true로 고정하고 단축키 목록과 콜백은 로드 시점에 한 번만 만듭니다. 현재 ID처럼 바뀌는 정보는 메뉴를 열 때 읽습니다.

1편의 키 목록이 이미 열 줄을 넘었다면, 그 줄들을 세 칸짜리 표로 옮기고 LEADER + . 를 붙이는 것부터 해 보십시오.

.wezterm.lua 다운로드

2026년 11월 5일 현재 PC에서 사용하는 전체 설정의 사본입니다. 내려받은 파일을 홈 폴더에 .wezterm.lua라는 이름으로 저장하세요. 기존 설정이 있다면 먼저 백업하고, Windows용 Git Bash·MSYS 경로와 글꼴·셸 목록은 본인 PC에 맞게 조정하세요. Herdr 연동을 쓰려면 앞 절의 키 설정도 맞춰야 합니다. Ctrl+U 다음 .으로 전체 단축키를 확인하고, s / e는 WezTerm 세션, q는 Herdr 분리라는 차이를 기억해 두세요.
