Android 폰으로 Wi-Fi 장비를 찾는 법

2026년 8월 8일

요약. 폰이 실제로 접속한 Wi-Fi의 사설망 대역에서 시작해 여러 종류의 로컬 근거를 결합합니다. TCP 포트, mDNS 이름, SSDP 설명, WSD 응답, NetBIOS 이름과 MAC 제조사는 각각 유용하지만 어느 하나도 모든 장비를 식별하지 못합니다. 응답이 없다는 사실도 장비가 없다는 증거가 아닙니다.

도토리 와이파이 스캐너검색 결과를 IP 주소·장비 종류·판정 근거로 표시합니다. 사용자가 복사하기 전에는 결과가 폰 밖으로 나가지 않습니다.

처음 들어간 작업장·사무실·가정 Wi-Fi에서 흔한 상황입니다. 폰 주소와 게이트웨이는 알지만 프린터·AP·NAS·TV·CCTV·컴퓨터·제어기가 어느 주소인지 모릅니다.

폰이 사용 중인 네트워크에서 시작한다

폰의 IPv4 주소와 prefix가 첫 검색 대역을 결정합니다. 흔한 192.168.0.0/24에는 사용 가능한 host 주소가 254개 있지만 prefix를 고정값으로 가정해서는 안 됩니다. Android 기본 네트워크가 바뀌면 이전 대역 결과를 비우고 새 대역을 반영해야 서로 다른 현장 결과가 섞이지 않습니다.

여러 발견 신호를 함께 사용한다

신호알 수 있는 것단독으로 부족한 이유
TCP 연결웹·SSH·인쇄·SMB·산업용 포트처럼 응답하는 서비스열린 포트는 protocol 후보이지 확인된 모델이 아님
mDNS / DNS-SD프린터·Cast 장비·모바일 서비스와 광고된 이름아무것도 광고하지 않거나 사용자 지정 이름만 내보내는 장비가 많음
SSDP / UPnPTV·미디어 장비의 모델 설명과 service type장비 상태와 네트워크 필터에 따라 응답이 달라짐
WSDWindows 방식 프린터·장비 발견전체 대역이 아니라 특정 장비군만 다룸
NetBIOS / hostname컴퓨터와 예전 네트워크 서비스의 이름이름이 없거나 오래됐거나 너무 일반적일 수 있음
MAC OUI가능성 높은 제조사제조사 이름만으로 장비 종류를 증명할 수 없음

이 신호들이 서로 보강할 때 분류가 쓸모 있어집니다. 프린터 service와 프린터 발견 응답의 조합은 제조사 이름 하나보다 강합니다. SMB와 NAS 근거가 있는 UPnP 모델의 조합은 445 포트 하나보다 강합니다. 약한 근거는 확정으로 올리지 말고 후보인 채로 보여주는 편이 정확합니다.

비용이 없는 것처럼 가장하지 않고 검색 깊이를 고른다

신속 모드는 짧은 대기를 우선합니다. 균형 모드는 느리게 답하는 장비를 더 기다립니다. 정확 모드는 안전한 HTTP metadata에서 제조사·모델 단서를 더 확인할 수 있습니다. 더 긴 대기와 protocol 작업은 분류를 개선할 수 있지만 VLAN을 넘거나 응답하지 않도록 설정된 장비를 억지로 답하게 하지는 못합니다.

‘미탐지’가 ‘부재’를 뜻하지 않는 이유

  • Client isolation은 폰의 인터넷 접속은 허용하면서 Wi-Fi client끼리의 통신은 막을 수 있습니다.
  • VLAN 분리는 대상 장비를 다른 broadcast domain에 둘 수 있습니다.
  • 유선 제어망이 무선 구간으로 routing되지 않을 수 있습니다.
  • Host 방화벽이 발견·연결 probe를 버릴 수 있습니다.
  • 절전 또는 부하가 높은 장비가 늦게 답하거나 전혀 답하지 않을 수 있습니다.

산업 장비는 가능성 높은 포트를 찾은 지점이 합리적인 기본 정지선입니다. 모델별 identity 조회는 선택한 후보 하나에 사용자가 승인한 read-only unicast로 수행해야 하며, 장비 전체를 향한 write 명령이어서는 안 됩니다. 본인이 소유하거나 관리 권한을 받은 네트워크에서만 검색합니다.
