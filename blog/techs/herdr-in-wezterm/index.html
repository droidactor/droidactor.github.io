Herdr: Keep Your Coding AIs in One Place

6 November 2026 · Updated 20 November 2026

In short. When you run several coding AIs at once, you keep switching windows to see which one has finished. With several projects open, you also stop to recall which task a result belongs to. Herdr groups your AIs and terminals by project. You can go straight to the work that needs you now.

A free app I built myself. Give it a try.

Herdr shows the state of each running AI and gives every project its own workspace and tabs. The terminals stay on a server, so you can leave and reattach to the same work later. You can also follow work on another computer over SSH. Commands that hand a task to another AI and read its output help you connect several agents.

I use Herdr inside WezTerm on Windows. Based on that setup, I show what gets easier with several AIs and how I arrange the work. It covers Herdr TUI, which runs inside a terminal, not the separate Herdr app.

You see first which AI is waiting for your answer

When several AIs are running, what you need to do changes each time. One AI is writing code, another has a result ready, and a third is waiting for an answer. Instead of reading the last line of every window, you check the states in Herdr's list on the left.

Here is how to read the states in the list. Each state also shows on the tab and workspace that hold that AI. Even while you look at another project, you can tell where to go next.

LabelMeaningWhat to do
workingBusy with a taskWait for the task in progress
blockedWaiting for an answer or approvalOpen the pane and make the decision
doneFinished, not yet viewedRead and review the new result
idleReady for inputSend a new request if needed

Say the review AI left a question while you were watching only the writing AI. When the list shows it waiting, you answer in the review pane and then check the writing result. Before you hand out more work, you see whether earlier work has stopped to wait for you.

You read the actual content on the AI's own terminal screen. The options a question offers and the command that just ran are right there. Status detection relies on the screen or on integration data. If a waiting state looks wrong, read the pane yourself.

Grouping projects and tasks makes them easy to find again

A Herdr workspace holds a project or a research topic. Inside it you create tabs, and each tab holds terminal panes. Put a bug fix for app A and the release work for app B in separate workspaces. The related AIs and logs then stay together.

Within one project, it also helps to keep coding, review and output in separate places. The coding tab holds the writing AI and the review AI side by side. The run tab holds the dev server and its logs. Panes are not only for AIs. Your usual shell, builds and tests go in them as well.

You also spend less time rearranging terminal windows when you switch projects. Pick a project in the list and you are back in the layout you set up for it. Reading a result, checking the related log and asking the AI again all happen inside one workspace.

You select a pane or drag a border to resize it with the mouse. The right-click menu splits the screen and creates tabs, and dragging over text copies it. You can use this layout before you learn any shortcuts, which makes the first days easier.

Leave the screen and come back to the same work

If you started a long build or test, you do not need to watch that window until it ends. Herdr separates the client that shows the screen from the server that runs the terminals. When you detach the client, the shells, AIs and running commands on the server keep going.

Reattach and you are back in the same terminals. You do not have to restart the AI and explain the situation again, or rerun a test from the start. The same project folders and pane layout are waiting for you as well.

This helps most when you leave a long task running and do something else. Leave the terminal with the build and the waiting AI in the same session. When you come back, check the result and then answer the question. You no longer have to finish the work before you can leave the screen.

Everything keeps running only while the Herdr server and the computer stay up. If you restart the computer or stop the server, the running processes stop too. The session state guide also tells layout restore apart from processes that keep running.

See the original computer's work from another device

If your work runs on a desktop at home or on a remote server, you can check it from another device. Connect to that computer over SSH and run Herdr to open its session. The code and the tools stay on the original computer. You watch and type from the device you connected with.

Picture moving to a laptop and checking whether a build has finished. Or picture reading an AI's question on your phone for a minute and answering it. The official documentation describes attaching to the same session from an SSH client on a phone. Herdr's terminal layout is built to stay usable on a narrow screen.

If you use several computers, save SSH machines and pick local or remote work in one Herdr window. The workspaces and agent states of connected machines appear in the same list. You no longer open a separate terminal each time to find the right session on the right computer.

Remote work keeps running on the original machine. Set up SSH and the network path to that machine first. It also helps to know which computer must stay on and where you will read the results.

Building agents that hand off work is easy

Besides letting you pick screens, Herdr gives you commands that control terminals and AIs. You can run a command in another pane, message an AI, read its output or wait for a state change. This helps when a script or a main AI takes over a hand-off you repeat.

For example, the writing AI can tell the review AI what to review once it finishes a change. You can also have a main AI read the review and write the next round of fix instructions. You stop switching between two windows to copy requests and answers by hand.

This needs rules for splitting the work. Decide which AI writes and which reviews, what each hands back, and when a person decides. Herdr provides the commands to create panes, send requests, read results and wait for states. You design the order of the work.

Start by running two AIs yourself, and connect the parts you repeat once you notice them. You begin with a few screens side by side and grow into automation in the same setup. The exact commands are in the official agent automation docs.

Splitting writing and review makes the workflow visible

To put these features together, take fixing one bug in an app. Create a workspace and place a writing AI, a review AI and a test shell in it. First decide how to reproduce the bug and what you expect, then give each role what it needs.

PaneIts jobWhat you check
Writing AIFind the cause and draft a fixThe requested behavior and the scope of the fix
Review AIReview the change and how it could failFindings backed by evidence, and missed conditions
Test shellRun builds and testsWhether it really passes, and the error logs

While the writing AI works, the review AI can study the related code or the conditions to check. When the fix is ready, send the review scope and check the results in the test shell. The AIs may move at different speeds. Give each next instruction in the order the results arrive.

If a test fails, read the log and tell the writing AI the failing condition. If the review AI asks something, go to its pane and answer. Once the review is done, judge the fix together with the test results. Each task's screen stays where it was, so rereading a result later is easy.

Decide that the work is finished by looking at both the state label and the actual output. An AI that is ready for input has not necessarily made the fix you asked for. A separate place for checking results leaves you evidence, even with many AIs running.

Use worktrees when each AI needs its own folder

If several AIs edit code, you need to separate the working files as well as the screens. Two AIs editing the same file in the same folder can overwrite each other's changes. Git worktree lets you check out another branch of the same repository into a separate folder.

Herdr also has commands to create or open a worktree. The new workspace is listed together with the original repository. For example, put a new feature and an urgent bug fix in separate worktrees. The code folders and the AI screens then stay apart.

To keep the edited files apart, point each pane at a different worktree folder. First decide whether the AIs read the same code and discuss it, or edit on different branches. Then create worktrees and merge the changes to match that choice.

Start with two panes in WezTerm on Windows

The setup I tested is native Windows Herdr 0.9.5 with Git Bash. WezTerm draws the terminal window, and inside it Herdr manages projects and AI work. You keep your familiar WezTerm fonts and colors and add Herdr's workspaces and sessions on top.

You do not need elaborate automation on day one. Put the AIs you already use and an ordinary shell in one workspace. Once you are used to checking results on screen, a review AI or remote access is easier to add.

  1. Install WezTerm and Git Bash, then install Herdr TUI by following the official guide.
  2. In WezTerm, go to your project folder and run herdr.
  3. Split the screen from the right-click menu and run claude or codex on one side.
  4. Use the other side as a shell for logs, or run another AI you have installed and signed in to.
  5. To leave the work running, detach the client, and attach to the same session again when you return.

The first time you run herdr, it starts the default session or attaches to the one already running. If you opened a named session, give the same name when you attach again. Use workspaces for everyday projects, and named sessions only when you need separate environments.

When a pane has a lot to read, zoom it and then return to the original layout. Selecting panes with the mouse and dragging borders covers most layout changes. Once the basics feel natural, add a few shortcuts you use often, and that is enough.

I share my settings so you can start from the same layout

My settings bundle (ZIP) holds my WezTerm and Herdr settings. It also has a Git Bash snippet that passes on the current folder. The shell is Git Bash, the colors are Catppuccin Macchiato and the font is JetBrains Mono. The window title bar color follows the Windows theme.

Back up your current settings first, then apply the files as the bundle's README explains. The README is written in Korean. WezTerm settings go in %USERPROFILE%\.wezterm.lua. Herdr settings go in %APPDATA%\herdr\config.toml. If Git Bash lives elsewhere, update the shell path in the file, and install the font yourself.

The current-folder snippet tells Herdr where you moved in Git Bash, so a new split opens there. It is small, but without it a split in your project folder can open a shell somewhere else. AI tools, their sign-in and remote access are not part of this ZIP, so set them up yourself.

The settings also include shortcuts that link WezTerm and Herdr pane actions. The keys are listed in the README and on the shortcut menu screenshot, which uses Korean labels. You do not have to adopt my shortcuts to use Herdr.

Add features as you need them

Herdr also supports plugins that build on your existing commands and terminal screens. If you keep setting up the same layout or commands, plugins are worth a look. The official docs list Windows plugin support as a preview, though. Start with the core workspaces and sessions.

Any terminal program works in a Herdr pane, and supported AIs also get state detection. Each AI supports state detection and session restore to a different degree. If you mix several tools, check the list of supported agents. Treat a done label as a signal that it is your turn to review the result.

Herdr shows the progress of every project and AI in one place. It takes you back to your original work and connects the hand-offs you need. Open one workspace with two terminal panes inside WezTerm. As you work, notice which checks and hand-offs you repeat, and you will know what to add next.
